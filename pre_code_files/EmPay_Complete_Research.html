Why Traditional HRMS Fails SMEs

📊

Most SMEs begin with spreadsheets. As teams grow past ~20 people, manual payroll tracking leads to recurring errors and compliance risks. Each fix pulls HR away from strategic work.

// System Design

System Architecture Research

Research across academic papers (PLOS ONE, PMC) and production HRMS platforms confirms that the optimal HRMS architecture for a web-based system is Browser-Server (B/S) with a layered MVC pattern. The older Client-Server (C/S) model is maintenance-heavy and poor compatibility.

Recommended 3-Tier Architecture for EmPay

🖥️
Presentation Layer (Frontend)
React 18 + Vite + Tailwind CSS. Role-aware routing via ProtectedRoute HOC. State via Zustand. Server state via React Query (TanStack). Charts via Recharts.
⚙️
Business Logic Layer (Backend)
Node.js + Express.js. Stateless JWT auth. Role middleware per route. Payroll computation engine as a pure service function. PDF generation via PDFKit.
🗄️
Data Layer (Database)
PostgreSQL 15 via Prisma ORM. ACID-compliant for financial records. Connection pooling for scalability. Prisma Migrate for schema versioning.

Key Architectural Principle: A typical HRMS must be divided into 3 functional layers — Basic Data Layer (employee records, salary structures), Business Processing Layer (payroll engine, leave workflow), and Decision Support Layer (analytics dashboard). This mirrors how Interact HRMS and other production systems are structured.

Production HRMS Architecture Lessons

  • Use Object-Oriented Design extensively to share components and optimize code (Interact HRMS pattern)
  • Workflow layer must be separate from business logic — leave approval triggers a workflow event, not inline code
  • Security layer must sit between presentation and application — all JWT verification happens in middleware, not route handlers
  • Database access layer (Prisma) abstracts all SQL — enables database portability and type-safety
  • Audit log table is non-negotiable for a payroll system — every mutation must be traceable

Module-by-Module Deep Dive

Module 1: Authentication & User Management

Research across Node.js RBAC implementations confirms the standard pattern: JWT stored in HTTP-only cookie (production) or Authorization header (hackathon). Role embedded in JWT payload for fast middleware checks without DB round-trips on every request.

// Standard RBAC middleware pattern (Express.js) const roleGuard = (allowedRoles) => { return (req, res, next) => { const userRole = req.user.role; // from JWT decode if (!allowedRoles.includes(userRole)) { return res.status(403).json({ message: "Access Denied" }); } next(); }; }; // Usage app.get('/api/payroll', auth, roleGuard(['admin', 'payroll_officer']), handler);

Module 2: Attendance Management

  • One attendance record per employee per day enforced via UNIQUE constraint on (employee_id, date)
  • Status logic: clock-in before 9:30 AM → Present; after → Late; no record → Absent (computed at payrun)
  • Admin override pattern: store override_by + override_note + original value in audit_logs table
  • Monthly calendar view: query attendance table for month, join with working day calendar to find absences
  • HR monitor view: paginated table with employee filter — same API, different role guard

Module 3: Leave Management

The leave workflow is a state machine: Pending → Approved | Rejected. On approval, two side effects fire: (1) leave_balances.consumed += total_days, (2) payrun recalculation flag set for that employee's month.

Module 4: Payroll Engine

The payroll engine is the most complex component. It reads from 4 tables (salary_structures, attendance, leave_requests, leave_balances) and writes to 2 tables (payroll_runs, payslips). All computation is pure and deterministic — same inputs always produce same outputs.

// Payroll computation pseudocode — pure function function computePayslip(employee, salaryStructure, attendanceSummary) { const basic = salaryStructure.ctcAnnual * 0.40 / 12; const hra = basic * 0.50; const specialAllow = (salaryStructure.ctcAnnual/12) - basic - hra - (basic*0.12); const grossSalary = basic + hra + specialAllow; const pfDeduction = basic * 0.12; const ptDeduction = getProfessionalTax(grossSalary); // Maharashtra slab const lopDeduction = (grossSalary / attendanceSummary.workingDays) * attendanceSummary.unpaidAbsences; const netPay = grossSalary - pfDeduction - ptDeduction - lopDeduction; return { basic, hra, specialAllow, grossSalary, pfDeduction, ptDeduction, lopDeduction, netPay }; } function getProfessionalTax(gross) { if (gross <= 15000) return 0; if (gross <= 20000) return 150; return 200; // Maharashtra PT max ₹200/month }

// Security Research

RBAC Design — Research & Pattern

Research across multiple Node.js RBAC implementations confirms the most scalable approach: embed role in JWT payload for fast reads, validate in middleware, enforce at both API layer (backend) and route layer (frontend).

EmPay's 4-Role Matrix

🛡️ Admin
Full access. No restrictions. Create/delete users. System settings. Override all data. View all modules.
👥 HR Officer
Employee profiles (create/update). Monitor all attendance. Allocate leave quotas. Cannot touch payroll or settings.
💰 Payroll Officer
Approve/reject leaves. Generate payslips. Edit payrun. View attendance. Cannot modify employee data or settings.
👤 Employee
Self-service only. Mark attendance. Apply for leave. View own payslips. View employee directory (read-only). No payroll access.

JWT Token Architecture

// JWT Payload structure — role embedded for stateless RBAC { "sub": "uuid-employee-id", "email": "jane@company.com", "role": "payroll_officer", // RBAC check in middleware "iat": 1717200000, "exp": 1717228800 // 8-hour expiry } // Never store sensitive data (salary, PAN) in JWT payload // Use RS256 in production; HS256 acceptable for hackathon

Frontend RBAC — ProtectedRoute HOC

// React ProtectedRoute — wraps all role-gated pages const ProtectedRoute = ({ allowedRoles, children }) => { const { user } = useAuthStore(); if (!user) return <Navigate to="/login" />; if (!allowedRoles.includes(user.role)) { return <Navigate to="/unauthorized" />; } return children; }; // Usage in router <Route path="/payroll" element={ <ProtectedRoute allowedRoles={['admin', 'payroll_officer']}> <PayrollPage /> </ProtectedRoute> } />
Security Note: Frontend RBAC is UI-only — never trust it for actual security. Backend middleware is the ground truth. The pattern is: backend enforces (HTTP 403), frontend hides (conditional rendering). Both layers must be implemented.

Database Design Decisions

Why PostgreSQL over MySQL or MongoDB

🔒
ACID Compliance
Financial data (payslips, salary) requires strict ACID guarantees. A payrun that half-writes is catastrophic. PostgreSQL's transactional guarantees are essential.
🔢
DECIMAL Type
PostgreSQL's DECIMAL(12,2) is exact for currency calculations. MongoDB's BSON double and MySQL's FLOAT both have floating point errors — unacceptable for payroll.
🔗
Foreign Key Integrity
Payslip must reference a valid payrun. Leave request must reference a valid employee. PostgreSQL enforces referential integrity at the DB level — no orphaned records.
📊
Analytics Queries
Dashboard requires aggregation queries (SUM, GROUP BY, DATE_TRUNC). PostgreSQL's query planner and indexing are superior for these patterns.

Why Prisma ORM

  • Type-safe query builder — TypeScript autocomplete prevents runtime query errors
  • Prisma Migrate creates versioned, repeatable migrations — essential for team of 2 sharing a DB schema
  • Schema-first approach: schema.prisma is the single source of truth for DB structure
  • Prisma Client handles connection pooling automatically — no manual pg.Pool configuration
  • Enums in Prisma map cleanly to PostgreSQL enums — role, status, leave_type all benefit

68% of Indian employees use mobile for HR tasks. Responsive Tailwind layout handles this. Key mobile flows: clock-in button, leave application, payslip download.
🔍
Predictive Analytics
Forecast turnover, identify burnout risk, align recruitment to growth projections. EmPay's analytics dashboard should show trend lines and forecasts, not just raw counts.
👤
Employee Experience
ESS portals, transparent payslips, real-time leave balance — these drive adoption. EmPay's employee dashboard must be clean and intuitive, not just functional.
⚖️
Compliance Automation
Indian payroll compliance (PF, ESI, TDS, PT) must be automated. Manual compliance is the #1 pain point for Indian SMEs. greytHR's success is built on this alone.
